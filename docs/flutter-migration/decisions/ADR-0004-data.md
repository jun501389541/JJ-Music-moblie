# ADR-0004：共享数据库与迁移

状态：**提案**；尚未建立 Flutter 数据库。

推荐 Drift + SQLite，关键数据统一事务；原生执行器不直写业务表。简单偏好可用平台键值，但不能存唯一歌单/恢复记录。Room 不作为共享核心。

保留旧 ID alias 和来源语义；内部稳定 ID 不表示按音频内容或歌名自动合并。schema、事务和导入回退见 [迁移](../08-data-migration.md)。

备选是其他经过 Android/Windows 事务、迁移和测试验证的 Dart SQLite 封装，不默认自建 ORM。批量 JSON 继续作为备份兼容格式，而非大数据主存储。

风险：跨 engine writer、WAL 备份、Android URI、文件与 DB 不能一起原子提交。采用单权威写入者、一致快照和幂等操作日志。失败保留旧资料，禁止直接升级唯一副本。

R3.3补充：P1只以05 C-03的窄文件原型验证恢复协议，不提前选择/实现本ADR生产数据库；P2替换装配并复验事务/升级/生产恢复。文件操作的归属/统一锁序/长等待边界只在08 O维护，P2/P5/P6批次展开时提交，不成为P1前置。

## 2026-10-31两端真实跨进程读回

同一端同一release探针保存flush凭据后由外部强杀，第二进程从同一隔离目录读取修订/fixture/位置/确认记录并默认暂停，两个平台均有实际PID与epoch证据。原型装配增加独立run目录的OS文件writer锁；没有跨进程正式DB/断电事务承诺。cache/code_cache可被系统清理，缺失/坏版本仍走安全空态。普通诊断运行与process-proof入口产物分开记录，P2仍替换端口、不双写。
