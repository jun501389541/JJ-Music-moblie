# ADR-0002：共享运行时与组件存活

状态：**提案**；无实现批准、无原型通过证据。

2026-10-30 PREP-01准备：按[本机计划](../tasks/prep-01-local-plan.md)将C-02短提交/独立控制派发、C-03真实隔离文件、C-05双端映射分别交A02、A02到A07、A03/A05。仅规划，不把API/fake当存活或恢复证据，架构字段仍提案。

问题：UI 生命周期不能成为播放/下载生命周期；一个 epoch 不能代表所有组件。需要独立于页面的运行时登记、唯一队列和数据库写入者。

推荐：共享 Dart 业务协调器；平台层持有解码/系统句柄，RuntimeHost 登记实例、命令 fencing 和运行资格。完整规范见 [架构合同](../05-architecture-contracts.md)。

备选：若插件无法保留所需 engine，调整插件/服务适配；必要时薄 Media3 服务持有当前及经批准的下一资源。原生只存恢复镜像，不独立计算随机/回退/歌单策略。

未知：排他接管的权威宿主在具体插件中放在哪里、能否跨 Dart 实例存活。A04/A07 和 B07/B08 必须证明；宿主一起死亡则 R3，不宣称 R2 平滑接管。

资源：逐轨句柄，不以身份提交撤销 outgoing；Broker/来源授权失效时硬撤销；下载独立使用者不随停止播放结束。

代价：需要清晰事件归属和恢复快照；不为此建设泛用 RPC 框架或复制两套数据库。失败时暂停并恢复，不猜状态。关联 TC-01—09、TC-24—30。

R3.3澄清（仍提案，不改变架构）：C-02只短串行提交，长操作异步且取消资格与释放分开；C-05由双端真实API映射形成项目确认及playbackConfirmationId，项目交接started不等于原始同名事件；C-03规定P1隔离文件适配器及跨进程读回，不依赖P2正式库。权威字段/规则只维护在05，验证为TC-05/56/57；无新全局门。文件锁序按08 O在P2/P5/P6细化。
