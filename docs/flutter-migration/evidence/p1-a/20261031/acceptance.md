# P1-A简单验收清单

这仍是技术诊断程序，不是正式播放器。只使用本工程生成的短音调。

1. Windows双击clients/flutter/build/windows/x64/runner/Release/jj_music_mobile.exe，整个Release文件夹要保留。Android安装clients/flutter/build/app/outputs/flutter-apk/app-release.apk；本批已安装到选定小米手机，应用名jj_music_mobile，内部调试签名。
2. 打开“自有样本播放诊断”，点“播放样本A”：当前应变成owned-a、确认数增加一次、位置开始推进；应听到短音调，实际听感请你确认。
3. 点“暂停”：位置应停止推进；点“定位3秒”再点“继续”：应从约3秒继续，确认数不因暂停/继续增加。
4. 点“切换样本B”：当前应变成owned-b，确认数增加一次，交接后资源应回到1；点“停止”后资源应为0。
5. 播放中点“UI重新连接”和“重建组件”：会话、当前音轨和确认数应保持；不能重头播或多记一次确认。
6. 暂停并点“保存恢复快照”，看到saved修订已落盘。Windows结束本诊断进程后重开；Android在应用设置强行停止jj_music_mobile，再重开并进入同一诊断页（不要清除数据）：应读回位置/修订、默认暂停、资源0，点“继续”才播放。技术强杀/两进程读回已有独立自动证据，正常关闭不代替它。
7. Android播放时回到桌面或关屏几秒再返回：应继续推进、不重建会话。当前小米短时后台/关屏及Activity重建已验证，长期省电/电话/蓝牙仍未验。
8. Windows播放时使用系统媒体面板暂停/继续/定位/下一首，应反映到同一诊断页。OS接口闭环已有自动验证，物理媒体键和系统面板外观尚待你实际检查。

已验证及未验明细见[阶段报告](report.md)。完整G-L暂不通过；真实持续缓冲/未知时长、独立engine/服务回收、输出失效等仍缺证据。Android额外按钮测试曾因再次自动关屏未完成；如复跑UI测试，先解锁亮屏，脚本仅测试期间保持本应用窗口亮屏，不绕过锁屏或修改全局配置。

不需要导入个人曲库或音源，不涉及账号/密钥，没有提交推送发布。不要安装app-debug.apk作日常入口，也不要把专用恢复探针当最终普通程序。
