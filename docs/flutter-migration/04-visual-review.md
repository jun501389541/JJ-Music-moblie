# P0-V：视觉稿与交互评审

**正式产品UI实施前必须用户确认。**本文件是交付规格，当前没有视觉产物或确认。权威批准记录在status.md，行为见交互文档；任务V01/V02。

## 交付矩阵

| 材料 | 最低覆盖 |
| --- | --- |
| 手机 | 列表+迷你条、封面播放、歌词、队列/历史、搜索/失败；竖屏与横屏/平板关键重排 |
| Windows | 侧栏/列表/播放条、宽窗播放、窄窗、队列/输出、桌面输入焦点 |
| 明暗 | 两端主路径，文字/边界/错误及背景对比度，不只换底色 |
| 压力稿 | 长标题、多歌手、缺图、无歌词、未知时长、部分失败、解析/缓冲 |
| 大字体 | 明确缩放与窗口条件；展示重排、滚动和仍可达控制 |
| 组件状态图谱 | 默认/悬停/焦点/选中/禁用、暂停/播放/加载/失败/重试及多选 |
| 动效说明 | 起终态、建议时长/曲线、手势冲突、反向/切歌中断、减少动画静态退路 |
| 可访问性 | 焦点/语义/读屏节奏/对比度；不只颜色 |
| 参考登记 | 官方描述D、直接观察O、JJ新提案P、待验H逐项区分 |

可以主屏稿+组件atlas覆盖多状态，不要求每状态一整屏；每项必须有可定位产物。不用可执行原型代替稿件，也不在本轮搭建产品原型。视觉工具自由，但不能把生成图标成竞品截图。需要素材许可时独立登记。

建议产物归档 `design/visual-vNN/`（本目录下），包含稿件、状态说明、交互说明、来源和评审意见。尚未生成则不创建空占位假图。目录名是建议，不是已授权增加产品代码。

## 评审与G-V

1. 核对产品规则、双端输入及内容压力；提交V01。
2. 用户对具体版本/页面/组件/动效表达确认，保留日期、范围、意见及例外。
3. V02写回批准记录与修订结果；没有回复不视为确认。
4. 实施任务引用已确认版本；重大布局/行为变更重新出变更稿。普通缺陷修复无需重问同一设计。

G-V不代表后端、性能、真实源或生产能力通过。技术诊断界面只可显示命令/状态/日志，不演变为正式组件库；领域、数据库、后端/宿主及合同测试可独立推进。
