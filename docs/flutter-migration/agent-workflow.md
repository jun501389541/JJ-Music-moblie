# 通用执行、验证、协作与交接

本页是执行/完成术语权威，不覆盖AGENTS，不依赖Codex/Claude Code/Cursor私有聊天、记忆、模型或并行工具。字段在05/07/08，依赖在tasks/README，文件角色在tasks/contracts-ownership，状态/授权只在status，实际证据保留于evidence。历史仅文档授权不覆盖后续新增授权；当前执行范围只看status和最新用户指令，手册细化本身不授权编码。

## 开工与批次循环

1. 从README读status/handoff/任务索引/相关合同，核实际仓库根、分支、完整SHA、未提交修改、目标规则。保留所有既有改动，不自动pull/reset/stash/清理。
2. 遵守现有GraphFlow规则：广泛探索前context，rootDir为实际项目绝对路径，使用summary/anchors/tokenBudget；多步实施前plan，变更后index。按已安装适用技能要求读取说明；不同宿主可映射工具名，不要求某个私有插件。
3. 查本次授权、前置实际证据、适用门/稿件、条件分支、文件owner与版本。详细任务不等于ready。没满足的实现不得开始；用户只需决定范围/产品取舍，类名和常规内部工程由agent处理。
4. 在status登记领取/owner/允许文件及本批证据位置，重读确认。每批一个可审查结果；已获阶段范围授权时，完成一批后可按依赖继续下一合格批次，不逐步重复请示。不越正式视觉/真实源/私人数据/破坏操作/发行等既有独立边界。
5. 先选本任务正常/异常/取消/并发场景及预期。行为变更/复杂故障优先建能暴露问题的失败测试或复现，再实现；纯文档、简单样式只做合适检查，不制造镜像实现的无效测试。
6. 按手册实现一个状态转换/平台适配/端到端路径，不一次堆播放器/曲库/在线/下载。长操作、事件确认、最小快照和锁等待继续引用05与08，不在页面/原生重写业务。
7. 跑相关验证、检查真实差异/owner/影响端，再保存证据与未验。新失败/接口变动/未解风险才扩大范围；测试通过且无新理由不反复全量运行。
8. 由协调者串行更新status/handoff、受影响ADR/合同/追踪；是否继续看已授权范围，不靠聊天“差不多了”。本批范围外停止，不把历史文档授权或已有代码扩大为全项目实施授权。

## 工具和环境前提

| 能力 | 开工前核对 | 缺失时 |
| --- | --- | --- |
| 仓库/文本 | Git、UTF-8、安全编辑、定点搜索优先rg、文档检查；实际root及修改摘要 | 无法保留/核对工作区不修改 |
| GraphFlow/规则 | AGENTS和要求的安装技能；可调用context/plan/index及返回要求的桥接 | 不能因换agent免除；按下表继续/阻塞 |
| Flutter/原生工具 | 阶段计划的实际SDK/ABI/JDK/Windows工具链、已审计依赖/资产 | 可做文档/合同；构建/运行不算通过，不在本轮安装 |
| 设备/网络/素材 | 对应端设备、输出/辅助技术/投放型号、自有fixture及许可/摘要、网络范围 | 缺端/真机/授权场景保持未运行；不拿其他端/fake替代 |
| 渠道/签名 | 具体产物/渠道授权及用户保管的密钥使用边界 | 先准备可审核候选；不写私钥进仓库/交接，不自动发行 |

未来已授权的依赖/构建批次内，常规本地依赖解析和修复不再每条命令请示；缺全局工具、未批原生产物、需扩权限/范围时才停该部分并给决定选项。所有命令含cwd/平台/前置/预期，产品命令见10；先读实际脚本，不因名字叫test就执行。真实资料/源不做默认fixture。

## GraphFlow不足的既有边界

| 状态 | 可继续 | 仍阻塞/不得宣称 |
| --- | --- | --- |
| context成功但无索引/锚点不足 | 记录返回，定点读相关文件/符号；后续仍按规则plan/index | 不编造事实，不全盘/私人目录扫描 |
| 工具不存在/context失败 | 保存清单/错误，已有授权内定点只读、文档修订/校验与证据整理 | 产品修改及需要GraphFlow前置的实施不可开始；rg不是GraphFlow成功 |
| plan失败/桥接未完成 | 只读核对、已授权文档计划与缺口登记 | 多步产品实施阻塞；启发式节点不等于最终计划 |
| 变更后index失败 | 记错误/未索引文件，可继续非破坏校验/交接 | 索引未完成、图可能过时；停止后续产品批次，不回滚他人文件救索引 |

仅缺服务商LLM密钥而工具返回agent桥接不等于服务不可用，按返回协议提交/合并，不读取或补配私人密钥。工具恢复后补缺失步骤并回写证据。这是现有强制技术前提，**不新增一层审批或豁免**。

## 只读基线命令

cwd为实际仓库根<repo>；前置Git，PowerShell/POSIX均可：

```text
git status --short
git branch --show-current
git rev-parse HEAD
git log -1 --format=fuller
git diff --stat
```

无网络时远程状态记未核；能联网可只读git ls-remote核远程，不能自动pull。任务拟新增文件本轮不存在，实施前先核真实树；具体插件API仅官方/上游及实际已选版本验证后写入计划。

## 结果术语与完成标准

| 验证结果 | 含义 |
| --- | --- |
| 未运行/not-run | 没有执行；写原因和缺失资源，不填成功 |
| 失败/failed | 已执行且不符预期；保输入/步骤/实际输出，不改N/A |
| 部分覆盖/partial | 仅列明子场景/端/版本通过，剩余明确未验或失败 |
| 不适用/N/A | 本批确实未启用或范围不包含且有依据；不能把原必需能力失败或无设备改N/A |
| 通过/passed | 对指定输入/版本/端/条件实际符合预期；不能外推其他设备/未来版本 |

任务状态唯一在status：proposed→ready→claimed→in-progress→review→done，另有blocked/needs-user。ready须授权、依赖、合同冻结、文件owner和验证资源满足；claimed是已登记范围；review是结果待集成/审阅；done须本任务必需验收及目标工作区集成有证据。规划可完成但实现仍proposed。用户反馈/实际私人实验缺失不得代签。

原型done、单元通过、分支通过、集成通过、风险门passed、视觉确认和发行是不同事实。单agent同工作区也记录目标工作区验证，不写“无需集成”跳过；多分支必须在实际集成目标重验受影响共同/平台路径。阶段收尾只汇总实际证据，不将整TC所有子场景或所有门自动全绿。

## 领取、变更与多agent

默认单agent顺序即可。多人先有协调者单写status/依赖/批准/当前handoff，每执行者登记任务ID、工作区/基线、allowlist、合同版本、预期验证后复读。文件不重叠且接口冻结才并行；具体角色/适用并行组只看tasks/contracts-ownership。无协调者/隔离时顺序，不要求自动互发消息。

共享接口/schema/锁/构建/令牌改动由唯一维护角色整合；提变更→列受影响任务/兼容/重验→暂停旧消费者→更新权威/实际版本→消费者复读再续。不能让原生与Dart各写队列/随机/重试/音质，不能覆盖他人未提交内容。阶段入口仅核真实路径和版本，不要求用户替agent决定常规内部实现。

工具允许且授权范围合适可用隔离工作树/分支；不因此授权commit/merge/push/publish。交付可用可审查实际差异/补丁和独立证据，不依赖共享聊天。分支自测先review；集成者核冲突/基线/owner，整合后重验，未集成不done。

## 出错后的出口

- 可自行修：已授权allowlist内可复现编译/逻辑/布局/测试问题，修最小层并复验受影响场景。
- 可换备选：仅已有批准且满足同合同/许可的备选，记录选用原因/版本及重验；不能偷偷改能力/业务语义。
- 应停该项：强制前置/必需设备缺失、文件冲突、需要扩大权限/未知原生资产/私人资料/真实源/破坏操作/发布范围，或无法解释安全数据风险。先做完不依赖它的已授权工作并留具体可审核选项。
- 禁止过关方法：删用例、降验收、吞错误、全局放开明文/文件访问、按超时抢锁、静默改用户语义、把失败改N/A。
- 回退仅本批可识别新增装配/差异，保最后有效数据及失败副本，不自动reset/stash/递归删除/覆盖他人改动。数据回退必须按08一致快照，不凭旧安装包。

## 每批证据与交接

证据用tasks/batch-record格式，最终规范仍见evidence/README。至少含：任务/范围与授权引用；分支/完整SHA/未提交差异摘要及本次实际文件；消费的C/M/D/schema/profile/稿件版本；自有fixture与摘要、平台/设备/编译/网络；cwd/命令或操作/预期/实际/退出码；五类结果逐场景；分支与集成层级；限制/失败/未完成/下一步；契约变化影响与原型处置。

每次更换agent前更新handoff：当前Git快照、已完成证据、进行中已改/未完、已跑和未跑原因、问题/决定/下一步、用户授权与待确认。状态只在status，交接引用不另建完成表。不同agent无需私人记忆；准确保留未完比“全部完成”总结更重要。
