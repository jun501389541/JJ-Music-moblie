## 保留的细节

基础业务键为 `local:id` / `online:source:id`，队列每次出现另有entryId。最近默认最多100，历史最多2。随机按完整身份处理一轮不重复、上一首及预留下一首，不在预载和自然结束时重抽。

当前自动音质预算作为迁移golden：总60秒、单次最多20秒；明确429受限一次重试；原平台优先、跨平台稳定tx/wy/kw/kg/mg顺序。同录音匹配保留当前测试的资料/版本/时长边界，不做同母带保证。更改预算/匹配先提产品规则变更，不各平台自改。

歌词sidecar优先内嵌；封面内嵌优先sidecar。已有本地资源不因联网自动覆盖。待写入按选择版本消费，失败保留，拒绝记录也属用户选择。现有MP3/FLAC内嵌写入范围不能因组件声明扩成全格式。

短过渡与双曲渐变独立；当前短过渡初值暂停/恢复150ms、启动/手动切歌300ms，尚非听感确认。渐变默认0关闭，0—12秒/1秒步进，仅合适自动下一首；试听、单曲循环、同身份、未知时长或有效重叠不足1秒走普通路径。交接后失败恢复仍可用旧曲，已发生incoming历史不删除。

## 搜索、排序与文本的兼容基线

F：固定提交见01；下表来自实际调用，不把搜索页与曲库内筛选统一成同一种算法。迁移golden在P2用自有夹具展开，未在本轮执行旧/新搜索测试。

| 入口/行为 | 当前事实及迁移保留边界 |
| --- | --- |
| 全局搜索的本地结果/联想 | `utils/local-search.ts:createLocalSearchIndex`：NFKC→toLocaleLowerCase→trim；标题、singer字符串、专辑组合。空查询返回空；空白分词后全部词可分布在组合字段内；仅去空白后纯ASCII字母额外匹配无声调全拼/首字母，数字/字母数字混合不走拼音 |
| 拼音范围/多歌手 | 当前pinyin-pro对代码检测到的汉字计算默认读音；多音字结果按锁定依赖和旧夹具，不承诺所有汉字扩展区。singer是现有合并字符串，索引其全文；不擅自拆分重排/去重多歌手以改变匹配 |
| 搜索排序 | rank依次为标题等于query=0、前缀=1、标题包含=2、标题拼音前缀=3、标题拼音包含=4；其他已匹配项回落3。rank相同用Intl.Collator('zh-CN')比较标题；比较仍相同保留输入顺序，不能擅加ID排序改变结果 |
| 曲库歌曲页筛选 | `LibraryView.vue:filtered`：trim+toLowerCase，在标题/歌手/专辑合并文本做整串包含；当前未调用全局拼音/NFKC分词索引。把这里改为拼音或跨词匹配属于另行产品变更，不当兼容修复 |
| 曲库排序 | name/singer/album使用zh-Hans-CN localeCompare；“added”实际按mtimeMs降序，不是导入时间。相同值保持输入顺序；不可静默改标签含义或用新导入时间替换 |
| 数字、大小写与Unicode | 上述locale排序未显式指定numeric选项，不以“更自然”为由改成数字排序。搜索NFKC只用于匹配，不改原资料、不用于文件身份；曲库筛选无同等归一化承诺。Dart/平台collation不能假定和Electron ICU逐项相同 |

TC-49扩充`src/test/local-search.test.mts`已有精确标题/多字段/全半角/拼音/数字用例的共享golden，还须含多歌手标点、组合/分解Unicode、全角空格、数字2/10、相同排序值、空值及排序同分输入次序。固定旧运行时/locale/依赖与输入序列，比较两端输出ID序列，不能只测“含目标曲目”；本轮只定步骤，不生成假golden。若无法兼容排序/多音字，先登记差异与候选规则，请求针对该用户行为的决定；不强制照搬JS运行时，也不先引入新拼音依赖。

这里的稳定次序指同一资料快照和输入序列下的同分顺序；目录枚举不承诺跨文件系统一致。旧列表/JSON的输入次序应在迁移快照中保留，不能通过新增ID兜底排序悄悄重排。跨次扫描若要改变同分次序，须先按本章行为变更约定说明。

线上平台查询保留原始提交文本与平台原ID，只按该平台既有查询规则映射，不能把本地拼音/大小写归一化无条件用于网络查询。输入/取消/分页缓存生命周期及文案管理权威见04新增章节，不在此复制状态机。

## 外部入口与实例范围

F：现有Windows拖放链`App.vue:onDrop → preload shell.importDroppedFiles → main IPC.filesDropped → MusicLibrary.importFiles/addFolders`是导入/刷新，不调用播放；目录加入先确认授权。`main/index.ts:second-instance`只恢复/聚焦窗口，没有消费argv；electron-builder.yml未配置fileAssociations，主入口未见open-file处理。未据此断言操作系统不存在任何手工关联或其他启动器；当前审计不能宣称已有文件关联播放。Android当前无实现。

| 入口/动作 | 本期建议与队列影响 | 保留/新增/阶段 |
| --- | --- | --- |
| Windows拖入一首或多首音频 | 导入资料，不自动播放、追加或替换当前队列；只授予所选文件能力 | 保留现有语义，P7桌面输入补齐；不是Android首发前置 |
| 导入/拖入目录 | 明确根授权后扫描，不启动播放；沿08扫描与权限边界 | 保留；普通曲库导入在P2/P3，Windows拖放在P7 |
| 第二次启动、无已支持的外部动作 | 激活原窗口，不建立第二writer或第二套媒体会话；不把未知argv当目录扫描命令 | 保留聚焦；参数播放是新增候选 |
| 文件关联/“打开并播放”一首 | **新增提案、待确认**：校验授权后提交C-02的PlayIntent单曲试听，不影响歌单；默认不注册入口 | 非MVP必需；若选择实现，先在P7前展开并确认具体语义 |
| 外部“播放这些文件”多首 | **新增提案、待确认**：显式动作提交按入口顺序的列表快照替换队列；“下一首/追加”只能是另一个明确动作，不能凭文件数猜测 | 与上一项同一可选范围；未经确认不自动关联或抢播 |
| Android打开方式/分享接收 | 系统URI是短期能力，不是路径；尚未纳入首版，也不默认在P7补齐；新增时先定单/多URI与授权生命周期 | 明确首版非目标；用户另选后展开任务并执行TC-51/52相关范围 |
| 脚本、歌词或备份文件的外部输入 | 不作为音频意图或隐式执行；仍走各自明确导入/预览/授权流程 | 不因外部音频入口新增而放宽既有边界 |

所有“播放”最终进入05 C-02的**PlayIntent**（即外部建议所称PlaybackIntent），沿用唯一PlaybackCoordinator；不新增平行队列接口。导入仅调用LibraryCoordinator，不以空播放意图唤醒/重置后端。

实例策略P：Flutter本期每OS用户只支持一个活动客户端实例，不支持便携版多实例（即使指向不同data目录）。业务DB另以规范化数据位置的排他占用防止不同启动形态共写；无法确认锁归属就拒绝写入并提示，不能仅凭超时抢锁。原生只接收/转交，业务授权、资源验证和意图决策仍在共享层。Electron与Flutter可按08并存，不能共库或自动恢复争抢音频。Android多Activity重连复用既有RuntimeHost，不另开应用级队列。

若实现外部动作：按启动请求ID与有界接收队列去重，重复投递返回原接收结果，用户再次主动打开产生新ID；只在受信本机实例间转交白名单动作/必要资源引用，不传shell片段、媒体token或任意配置。未ready时只接收为pending，不能冒充applied/playing；超时/超限明确拒绝，不无限保存敏感参数。旧实例退出/通道断连时先核权威和接收回执，不能两端同时执行。就绪后重验URI/文件权限、类型/数量/来源，失效提示重新选择，单文件权限不扩成父目录权限。具体消息字段/生命周期在该可选任务展开时回写05；当前不为此改P1合同。TC-51/52在对应功能阶段验证。

## 本次用户行为变更提案（不计兼容修复）

以下提案需后续针对行为收敛：可选文件关联的单首试听/多首替换及Android分享；首发系统备份白名单/不支持范围见08；诊断导出预览及7天保留建议见10；04的IME保护/150ms防抖是Flutter输入建议，当前输入法行为尚未真机核实，不能当已复现缺陷修复。08的链接/云占位MVP限制及本章便携多实例不支持也是明确的支持范围提案；若旧用户依赖这些能力，应保留为P7/P9迁移差距，不能宣称旧版从不支持。

08提出的“已有条目临时标签解析失败保留旧标签”也是保守新策略；当前readTrack失败返回文件名基础信息，不能称已有保旧行为。受管孤儿回收/缓存配额及诊断期限均为新存储政策建议，需在对应阶段按本章变更约定收敛，不以“可重取”为由直接删用户资料。

上述均未获行为批准，不因此扩充首版。全局与曲库筛选差异、mtime排序、拖放不播放按现状保留；自然数字排序、统一筛选算法、多实例和自动云盘下载不自动采用。阶段前如提出改变，先更新本章及相应ADR/任务/TC；本轮只补边界，不宣称修复软件。
