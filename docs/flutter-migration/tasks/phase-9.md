# P9：详细任务手册—替换与必要维护

本页为R4实际填写的任务；状态/授权只在[status](../status.md)，前置唯一在[索引](README.md)。所有Flutter/原生路径均为**计划新增或未来真实树待核**，本轮没有工程；未选依赖不预写插件方法。阶段入口只把既有手册与当时真实原型/树/工具对齐，不重新设计整套架构，也不增加审批门。在已授权阶段内可连续完成符合前置的独立小批次，独立视觉/私人源/发布边界保留。

共同读取：[批次运行与结果术语](../agent-workflow.md)、[契约/文件归属](contracts-ownership.md)、[条件分支](conditional-branches.md)、[测试权威](../10-testing-release.md)。每个任务把适用TC拆到自己的正常/异常/取消/并发子用例，局部通过不把整TC或风险门自动标通过。

## P9-00：替换条件与差距评审包

- 目标与用户可见结果：用户可据实际差距决定是否替换Electron
- 依据与产品规则：避免关键设备/数据未验导致业务或数据语义错误；PR-16/24/25。语义以[03](../03-product-rules.md)为准。
- 关联需求：R-14、R-16、R-19、R-22；需求定义及任务/核心测试映射唯一见[12](../12-requirements-traceability.md)。
- 范围与非目标：只评审，不自动冻结旧版或宣称零bug
- 前置与授权：仅以[任务索引](README.md)的P9-00行及[status](../status.md)为准；本手册不授权开工。对应阶段范围已授权；仅启用已满足能力门的功能；已授权范围内常规修复持续完成，不逐步重新请示。
- 环境与自有数据：Git、UTF-8编辑/定点检索及文档检查工具；只读核对现有SDK，不安装、不运行产品。 数据/规模：自有夹具：必需路径证据完整；关键设备/数据未验；用户延后决定；不同版本证据混用。
- 输入输出契约：09 P9、10发布、功能差距；开工记录文档R4及实际合同修订/文件摘要。公共消费字段由P9-00按前置证据锁定；消费前未冻结不进入相应代码改动。本任务负责的实验输出不要求预先通过，可在安全输入/授权满足后做限定实验；不把本文路径当已存在。 输出：替换条件与差距评审包的实现/限制与可复现用例结果。
- 允许文件与负责人：既有本目录相关任务/ADR/交接与本任务证据；不改产品。 P9-00执行者只负责上述范围，共享模型/schema/锁/构建/设计令牌由[归属表](contracts-ownership.md)指定角色串行整合，不自行改。新增目录外文件先回写当批allowlist，不默认全仓库。
- 正常/异常/取消/并发场景：正常=必需路径证据完整；异常=关键设备/数据未验；取消=用户延后决定；并发=不同版本证据混用。逐项记录实际覆盖；规划任务只审条件分支，未运行或未发生项保留未验，不为凑齐制造测试。
- 验证方法：cwd <repo>；按DOC-01—05检查实际文件/引用/依赖和计划清单，不为规划强行跑产品套件。 TC=DOC-03/04、TC-37/45证据审阅，等级沿10注册表；命令/编译模式及预期在当批证据写明。
- 完成标准与证据：差距可追踪；用户看到真实风险；用户只决定产品取舍；四类场景按本任务适用TC留实际结果；保存`evidence/P9-00/<batchId>.md`（计划新增），含完整代码SHA/未提交差异、合同/稿件版本、自有fixture摘要、准确cwd/命令/步骤/退出码/限制及分支与集成结果。适用TC每个子场景可定位，未验项不得记通过。
- 条件与待定项：插件API、具体schema/文件细节在P9-00按前置证据冻结；其余按本任务范围自行选择并回写，不问用户内部类名 成功/失败与原型处置以[条件分支表](conditional-branches.md) E9/E12为共同约束；具体选择回写对应ADR/任务，原型不自动进生产。
- 失败出口与回退：保留失败现场与最后有效数据；仅恢复本任务新增装配，不覆盖旧客户端或他人修改 常规编译/局部逻辑错误可在allowlist内修复并重验；换候选仅限已批准且满足同合同者。需要扩大权限/改变语义/私人数据/未批依赖或删测试降验收时停止；保留本批改动和失败证据，不能reset他人工作。
- 独立可继续工作：索引中其他文件不重叠且前置已满足的任务；仅限已有授权且前置满足。
- 下一任务：协调者据索引选择已满足的后继；建议检查P9-01需用户实际决定，不自动授权/跳阶段。
