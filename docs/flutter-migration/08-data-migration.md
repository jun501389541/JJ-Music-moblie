# 数据、备份与旧客户端迁移

分类F/P/H；ADR-0004提案；完整实现P5/P7。禁止本轮读取真实用户资料。样本使用生成/脱敏夹具，真实数据需独立授权。

## 输入格式与身份

当前settings.json含设置/最近/LastSession/queueHistory；playlists.json v1含完整有序条目；library/index.json v5含路径标签/assets；library/pending-assets.json含待写入与拒绝；downloads.json含传输/入库；sources/user_api.json含脚本；local-relink.pending.json含恢复日志。数据位置可能显式指定、指针、便携data或AppData，不只固定系统目录。

现有导出`kind=jj-music-playlists, version=1`仅白名单歌单信息，20MiB/1000歌单/50000曲目边界，不是全应用备份。restore新建（恢复）歌单，不覆写default/favorites身份。

Track内部稳定ID可改进存储，但保留legacy alias及原平台原ID；不是按歌名、内容或同目录自动合并。原生身份类型和解析必要字段不丢失。queue occurrence另有entryId，可表示同曲多次。

## 事务、升级与一致性

歌单/队列按expectedRevision事务；扫描按目录与文件修订复核，晚读取不能复活删除或覆盖写入。单业务writer，即使多engine入口也通过同权威实例。下载执行器只检查点，不直写业务表。

升级先一致备份→临时副本迁移→integrity/外键/计数/顺序/alias检查→成功切换。运行SQLite用Backup API或已验证一致快照，不仅复制主DB忽略WAL。[SQLite官方](https://www.sqlite.org/backup.html)。旧schema到新schema逐版本测试，未知高版本拒绝降级写；失败保留旧库及失败副本。

文件与DB通过幂等日志：已发布未入库只补入库；标签写成功未提交重读核对；不重复删除/覆盖。不依赖退出回调必达。

## 三种迁移

| 场景 | 流程 |
| --- | --- |
| Android导桌面v1备份 | 仅导实际字段；Windows路径作线索，本地标未定位；用户授权目录后预览映射，模糊匹配不自动确认；无文件不删歌单项 |
| Windows同机全量 | 用户选旧目录，旧进程退出或先明确一致快照；只读副本，不能调用会重命名损坏原JSON的旧读函数；校验/预览/新库导入，原目录不写 |
| 新旧并存 | 不同应用ID/数据目录/DB/更新通道；一次性快照，不持续双写；重新导入明确新建/跳过/预览合并；避免双端自动恢复抢媒体 |

可迁：歌单/收藏/收集箱/顺序，最近/会话/历史，原身份及非敏感解析字段，验证后的来源链/选择/待写入/拒绝记录，映射设置，已完成下载状态。迁移音乐文件位置需再验证。

不迁为有效运行态：临时URL/令牌/头、IPC/进程/心跳、in-flight请求、运行generation、失效缓存、浏览器GPU数据、未验证part授权、不可映射设备ID。退役consent字段不复活。普通歌单备份没有的历史/来源不能伪造。

脚本不随普通备份自动启用；跨平台单独选择/兼容。待写入原目标与新目标须预览，不因relink静默写新文件。缓存与用户选择分开，清缓存不丢待写入。

## Android文件能力与安全写

MediaStore/SAF返回授权引用，不假设能转绝对路径；持久授权重验。FileAccess报告read/seek/createSidecar/writeTags/atomicReplace/delete/可持久权限。

DocumentsProvider不保证Windows式原子rename。无安全替换能力时导出副本/sidecar，不放宽权限。MP3/FLAC写入先目标/指纹预览、释放读取、写副本/校验/发布、重读索引、CAS消费。自动扫描/联网匹配不得写音频。

恢复预览展示输入格式/时间、数量、冲突/不支持、未定位、丢失资产与不迁项；取消无写入；导入失败旧客户端继续可用。P9前演练真实授权资料的退回路径，不假设新库可被Electron读取。

## S：存储分类、预算与清理

R3.2补充，分类P；资源持有/释放继续以C-04、D-04/D-07和本章事务/operation_journal为准，不另建一套租约或DB写入者。以下预算是待实施测量调整的设计初值，不是实测能力，也不扩大P1探针。

| 分类 | 预算/保留策略 | 可清理边界 |
| --- | --- | --- |
| 业务DB、歌单/收藏/历史、用户选定歌词封面、待写入/拒绝记录 | 不按缓存额度自动淘汰；统计占用并告知增长；DB压缩需独立临时空间与维护时机 | 仅明确业务删除/迁移；用户确认资料即使可联网重取也不是缓存 |
| 设置、授权引用、音源元信息/脚本文件 | 设置体积有界；脚本导入逐项限额在P4锁定，超过上限拒绝导入，不驱逐已安装源 | 脚本属用户安装资料且可能含凭据；由音源卸载流程处理，非清缓存 |
| 用户音频、下载成品、用户导出的备份/sidecar | 不设自动淘汰额度；按用户选定存储卷核容量 | 不因删除下载记录、清缓存或卸载源而删除；音频删除独立授权 |
| 正在使用/暂停可恢复part、staging及导入/标签副本 | 每卷预留预算，实际长度/检查点核对；暂停任务不按缓存TTL删除 | 复用D合同；只有显式取消并选择清残片，或确证无所属操作的受管残留，才进入回收 |
| 自动资料/封面/歌词及可再提取封面缓存 | 建议总额256MiB，封面字节子额192MiB、歌词16MiB，其余共享剩余额度；LRU+来源有效期 | 仅无用户选择引用且无活跃持有的派生物；用户选择/待写入须独立持久副本或pin引用 |
| 结构化诊断日志 | 容量/期限唯一见10“最小诊断”；不计入用户资料预算 | 按该章轮转，导出的用户文件不随日志轮转删除 |
| 无操作归属的受管临时/失败残留 | 建议24小时宽限并在两次独立盘点确认后回收；扫描批次/临时项计数有界 | 只在应用拥有的临时目录及命名空间内；未知归属保留并报告，不遍历删除用户目录 |

256/192/16MiB借当前Electron `online/cache-budget.ts`预算作初值；不是把在线缓存加入本地MVP。P2/P3只为已经使用的本地派生缓存设置有限预算，P4/P6再启用相应桶；未来在对应阶段计划固定计量口径（文件实际字节、索引、WAL和正在生成部分均计入）及高/低水位，不能为过关临时提高额度。全局大文件管理器、自动清用户资料、云盘管理均非MVP必需。

清理流程：先取权威持有快照并申请短删除预约（防新读者进入但不妨碍现读者释放），核播放/预加载、下载、导入、标签写入/待写入及备份→仅挑可安全回收的受管候选→按下文O节冻结的锁序取得实际删除互斥并复核文件/内容修订→逐项删除与幂等记账。需要播放器释放时先退出会阻碍释放的锁/事务，再异步等待；不能持独占锁等待读者释放自己。候选列表不是授权；复核至删除间不得出现新读取者。共享blob任一保留引用仍在则不删；不是当前曲目不表示旧轨无用。不能安全删除则延后，不强撤租约；归属无法确认则跳过，不靠TTL认定死亡。

满盘：按目标卷估算新增字节、可能的整文件副本、DB/WAL/操作日志及安全余量；建议预留余量初值64MiB，具体值在P2/P5的设备/大文件实验前确定，不声称该值保证原子性。未知长度传输使用有限分段预约，余量不足即暂停。先回收合法派生缓存，仍不足则拒绝新缓存/导入/下载/写标签，不删除用户资料救场。ENOSPC/配额失败分为持久化失败与播放失败，既有可读音轨不必停；保留旧DB/文件、有效part与上次检查点。磁盘已无法写新日志时不得伪报已持久化，使用最后有效记录及实际文件恢复；缓存失败可无缓存继续，关键事务失败明确提示未保存。自动重试不因同一满盘错误循环，须空间变化或用户操作才重新评估。

| 用户动作（如有该入口） | 影响 | 保留/限制 |
| --- | --- | --- |
| 清缓存 | 失效并回收可淘汰派生桶，活跃持有延后；重新获取仍受网络/音源权限 | DB、歌单、选择/待写入/拒绝、成品、part、脚本均保留 |
| 删除下载记录 | 先按D-07停止执行/入库，移除任务记录与明确选定残片 | 默认保留成品/曲库/歌单；未确认停止保留记录，不制造无主writer |
| 删除音频 | 独立确认目标及应用拥有的sidecar，按FileAccess能力执行并协调扫描 | Windows优先回收站；不支持不静默永久删除；Android删除能力/系统确认单独验证；歌单条目不隐式删除 |
| 重置设置 | 只重置入口明列的非权限偏好 | 不清曲库/歌单/源/授权或隐式启用脚本；该入口不是首版必需 |
| 清空应用数据 | 若提供，显式说明本地DB/私有资料/脚本/检查点丢失并先停止所有writer/运行持有 | 外部用户文件/用户导出备份不随删；私有目录成品若将被平台一并清除必须预警；不假称可撤销 |

应用内未实现上述动作时不提供假入口；系统清应用数据/卸载不受应用回调保证，首次发行须说明私有数据丢失边界。TC-47覆盖预算、持有、孤儿及满盘，TC-30/36/37继续覆盖已有业务竞态，不复制其规则。

## L：扫描边界与文件身份

P2/P3 MVP建议范围：用户明确选择的普通本地目录/文件，以及FileAccess已经证明可枚举/读取的Android授权URI；格式范围沿现有扫描白名单与实际后端能力。首次不承诺遍历符号链接/junction、网络共享、云盘自动下载或所有DocumentsProvider。授权目录之外不自动扩根。

| 情况 | 扫描与身份规则（P；F基线见01补充审计） |
| --- | --- |
| 重叠根/重复授权 | 相同提供方document身份或已确认同一文件位置只提交一次扫描结果；根与文件是多对多覆盖，不因移除一个根删另一根覆盖的条目。保留各授权引用及其有效性；不只比较显示路径 |
| 符号链接/junction/循环 | MVP默认不跟随，显式根也先检测/提示不支持；平台无法可靠识别时有界深度/条目/时间并标partial，不能无限走树。未来若启用须限定授权边界并按已访问目录身份防环，另展开验证，不靠字符串前缀作权限证明 |
| 大小写/Unicode/长路径 | 保存原始路径/URI；仅平台证明的文件位置等价用于去重，不能把搜索NFKC或全局lowercase当文件身份。大小写敏感目录保留区别；无文件ID时只按已验证的位置键保守去重。长路径由实际枚举/读取/写入分别验证，失败记不支持/不可访问，不截断路径重试 |
| 可移动盘/根离线/撤权 | 根标暂不可访问、保留引用及快照；卷标/盘符相同不足以重认同一设备，重新访问核卷/位置。不可访问不等于确认删除；完整扫描成功且文件明确不存在才更新缺失状态，歌单身份/用户选择不被级联清除 |
| 云盘占位文件 | 不默认为提取标签触发批量hydration；可检测则跳过并提示未下载，无法区分则有界读取并标限制。显式点播/用户选择下载由独立能力处理，MVP不承诺自动离线化 |
| 同文件/同内容/同名 | 重复发现同一已确认文件位置去重；硬链接是否同位置由平台能力与迁移映射决定，默认不折叠用户已有条目。不同位置相同内容、同名歌曲均不按内容合并；指纹只辅助定位且预览确认，legacy alias歧义报告而不覆盖 |
| 正在下载/写标签/移动 | 受管part/staging不索引为成品；与operation_journal及所属路径写入互斥，发布后才可入库。外部变动以读取前后位置/size/mtime及可用修订复核，不稳定只标待重扫，不用过时元数据覆盖新结果 |
| 中断/解析失败 | 扫描epoch/根修订及提交检查复用本章事务合同；取消后未核实范围不做移除，已安全提交的增量可保留并标未完成。新文件标签解析失败可按文件名建立基础信息、保留错误类别；旧条目临时失败不覆盖已有有效标签；不是自动忽略坏文件而宣布全量成功 |

枚举/解析并发、深度与条目上限在P2展开时按自有目录夹具确定；达到上限保留partial及继续/缩小范围入口，不标完整扫描。搜索索引用已提交的曲库revision，不能读到半批发布。路径等价规则属于FileAccess适配，条目身份/去重与扫描提交在共享层；不在Dart和原生重复实现合并政策。TC-48覆盖本节，已有撤权/重定位/晚结果仍引用TC-35。

## O：文件操作锁序与等待（对应阶段实施前细化）

本节为唯一规则来源，消费C-04的释放确认与D合同、operation_journal/修订检查，不改变其接口或业务所有权。P2的数据/扫描/播放，P5的下载发布/迁移，P6的标签/资产写入，在各自批次开始前必须提交下表并由共享文件负责人冻结。**不扩P1，不预设mutex、actor、文件锁或某个锁库实现，不建设通用锁框架。**

| 实施前必交内容 | 约束/验收 |
| --- | --- |
| 资源/归属表 | 列根与文件位置/URI、blob/sidecar、part/staging、发布目标、DB/操作日志、后端handle等实际冲突资源；复用既有协调器owner，区分短状态锁、文件读写持有、长操作预约；同物理目标的别名/重叠根须能一致协调，不因此合并业务条目 |
| 统一获取顺序 | 对会同时获取的资源定义共享顺序及多文件稳定排序，标出会跨协调器调用/回调的边；禁止反向持锁获取。单一全局大锁也不豁免长等待约束；不能让清理、扫描、下载、写标签各自约定一套相反顺序 |
| 事务与等待边界 | 数据库事务不跨网络、JS执行、播放器停止/释放确认或长文件I/O等等待；不持DB/路径/blob独占锁或其他阻碍释放的互斥等待后端释放。准备/协商在短事务外，文件发布与DB提交分段并用日志/修订复核衔接，不能伪称跨资源原子事务 |
| 预约与释放路径 | 若需先预约防新读者，预约必须允许既有读者释放和取消，不占住其回调所需锁；等待前退出相关独占锁/事务，取得确认后按固定顺序重新获取并校验修订/权限。不得持command提交队列等锁来等待异步完成 |
| 超时/取消/中断 | 明确每个等待的有界期限、谁可取消、取消后发布资格及实际释放/清理的后续责任。超时不表示已释放或可抢写：跳过清理、延期写标签/发布、保原文件/有效part/待写入及检查点，报告pending/可重试类别；取消预约不伪造文件回滚，进程死按日志/实际文件恢复 |
| 交错测试矩阵 | 以受控屏障交错播放/预载/旧轨释放、清理、扫描提交、下载发布、标签写入；覆盖相反请求顺序、多目标/别名、取消/超时、回调乱序/进程中断及重试，核死锁退出和数据一致性，不只跑各功能独立成功路径 |

共同不变量：无死锁/无限持锁，超时仍不误删在用文件，无双writer/覆盖唯一副本/晚扫描复活，已发布未提交可幂等补账，失败不消费待写入。业务不必为等锁冻结播放控制；真实后端不能及时释放的能力限制需显式记录。TC-58由P2/P5/P6按相应资源组合执行，先离线受控交错，再实平台文件与后端验证；不能仅凭锁序文档宣布无死锁。

## B：平台系统备份与目录复制

系统备份不等于应用歌单JSON备份，也不增加账号或同步服务。平台可能自动搬运应用目录，不能仅凭“普通备份不启用脚本”推断已排除脚本。首个对外Android包之前必须给出明确配置和恢复测试；P3本地发行只验证下列安全边界，不提前实现P5完整备份。

| 数据 | 应用受控备份/恢复建议 | 系统或外部复制后的行为 |
| --- | --- | --- |
| 安全偏好、无秘密的歌单/用户选择资料 | 应用备份沿白名单；系统备份只允许经审计的安全投影/独立偏好 | 校验版本/完整性，恢复后默认暂停；缺文件/授权保持待定位 |
| 原业务DB/混合偏好 | 可能含路径/授权或源配置，不因扩展名是DB/JSON就整库纳入系统备份 | 首发建议默认排除；若要纳入，先证明已分离敏感字段及一致快照，不能靠字符串替换过滤SQLite |
| 脚本/其内容内凭据、源私有配置、密钥 | 默认排除云备份、设备迁移、诊断及普通歌单备份；不能声称能识别脚本中的全部秘密 | 用户主动独立迁移也只能先禁用/隔离、重新授权和兼容验证；不执行后再询问 |
| URI/文件授权、设备/输出ID、实例/令牌/临时URL、part执行态 | 排除有效运行态，参考本章“不迁项” | 重验权限/文件/表示；不能以旧授权引用或旧owner恢复执行 |
| 日志、崩溃资料、缓存、临时副本及下载成品 | 系统备份默认排除；成品由用户自行管理，普通JSON不承诺复制音频 | 不作为必须自动恢复的资料；旧执行检查点不可直接重播 |

建议首版只做安全偏好白名单，其余系统恢复能力明确不支持；如果白名单尚未证明安全，则显式关闭能关闭的系统备份并配置各传输模式的排除规则，不使用Manifest默认值作为策略。Android云备份与设备间迁移需分别核查，`allowBackup=false`不能替代所有厂商/系统上的设备迁移排除证明；系统版本、targetSDK和厂商行为在实施阶段复核。[Android官方备份/排除说明](https://developer.android.com/identity/data/autobackup)（2026-10-30核阅）。该项属于新平台分发设计建议，待审核，不是已修复缺陷。

Windows应用自己的导出/迁移须按分类打包，不直接压缩整个data目录。用户用资源管理器任意复制目录可能带入脚本/诊断，应用无法保证外部拷贝已脱敏，也不能保证检测每次目录复制。受控恢复/异机迁移入口必须默认禁用脚本、重验来源摘要与本机授权；无法确认受信安装/权限时不自动运行脚本。新库目录复制仍须满足单writer和一致快照，不能复制正在写的主DB当备份。签名私钥/口令由用户控制，不写仓库、证据包或普通交接记录；公钥/证书标识与资产摘要可记录，秘密只记录“由用户提供/不可用”。TC-54使用自有带敏感标记的夹具验证排除/恢复，不读取私人数据。
