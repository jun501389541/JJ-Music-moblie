# 给新手的一页使用说明

现在已有Flutter双端技术诊断和自有本地播放/恢复原型；**不是正式播放器，完整G-L仍未通过**。先读README、status、handoff；不需要理解每个内部类名。

## 我现在该怎么开始

审核后可先说：“只允许执行PREP-01，做环境核对和P1-A批次计划，不安装、不创建工程；完成后交接。”这仍是文档/只读规划。想先看外观可另授权PREP-02/V01，正式页面必须等你确认具体稿件版本。不要直接说“把所有阶段做完”，先确定一个阶段/批次及范围。

已经明确授权某阶段后，agent应按依赖连续完成可审查小批次、修常规错误并验证，不该每条命令都问你。阶段结束/越范围/已有独立边界才停；内部类名、正常测试命令和局部实现方法由它负责。

## 换agent时做什么

把[start-prompt](start-prompt.md)给新工具，让它从仓库入口读起。要求先报分支/完整提交、未提交文件、当前任务/合同/稿件版本及已验证/未验证。不要让它默认“上一个说完成就完成”，也不要让它清空、回滚或覆盖未提交文件。不同工具仍须准备GraphFlow等仓库要求的能力，故障时只能按workflow允许的边界继续。

只有一个agent时照任务索引顺序即可。多人时需要一位协调者单写status/交接，登记不重叠范围；没有协调者/隔离就顺序做，不能靠多个聊天同时抢同一文件。

## 怎么判断真的完成

让它给你本次任务ID和可点击证据：实际代码差异、用过的合同/设计版本、输入/操作/命令、结果/退出码、两端分别验证、没测什么及原因、是否已在目标工作区完成集成。只给“页面有了”“编译成功”“全部完成”不足以证明播放器/后台/迁移可靠。

未运行、失败、部分覆盖、N/A、任务done、风险门passed是不同结论；N/A必须因为未启用/不适用且有依据，不能把失败改成N/A。Android过不代Windows过，合成不代真源，文档检查不代产品测试。缺必需证据应review/blocked并准确交接。

## 哪些事情需要我决定

产品取舍/新增行为、视觉稿版本、实际设备/私人音乐或源实验、正式标识/渠道与签名保管、破坏性数据操作、具体产物发布、替换旧端。agent应先准备具体可审核结果，再给推荐、替代、影响和最晚决定点，详见[条件分支的决定表](tasks/conditional-branches.md)。不要把签名私钥、账号或私人音源直接贴进普通交接/仓库。

遇到扩大权限、全局明文、删除测试/降低验收、忽略错误、未经确认改语义或让两个进程共写数据，应要求停止该危险部分并保留证据。正常编译/布局/局部逻辑问题由agent在已授权范围内修复；无法完成就保存未完文件、失败输入和下一步，不应宣称全部完成。

最终检查两个文件：status有真实状态/证据，handoff有当前改动/未完/未测/下一步。它们是交接入口；不用共享私有聊天或记忆。清晰合同、小批次、自动与平台验证可以降低风险，不能保证不会出现bug。
